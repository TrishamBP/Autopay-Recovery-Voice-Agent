# Backend feature workflow

## When to use

Use this when adding or changing behaviour: an HTTP or WebSocket endpoint, a domain service, an LLM tool, a provider adapter, a model or migration, or a script. For review-only requests, use `async-review`, `websocket-review`, or `architecture-review` instead.

## Inputs and prerequisites

- A feature description (`$ARGUMENTS`) or the user's request.
- Read `.claude/CLAUDE.md`, `.claude/rules/architecture.md`, and the rule files for the area you'll touch. Path-scoped rules may not have loaded yet if the files don't exist.
- For anything touching customer, payment, note, or call fields, read `../synthetic-data/data/DATA_DICTIONARY.md`.

## Workflow

1. **Inspect.** Find the modules, tests, and settings this feature touches (Glob/Grep). Note the existing patterns, and don't assume a module exists.
2. **Clarify the contract.** Write down the inputs, outputs, error cases, side effects, idempotency, auth, and which domain owns it. If a requirement is ambiguous, or the feature needs a new dependency, infrastructure, or a breaking change, **ask the user before coding**.
3. **Plan briefly.** List the files to create or change, state the key design choice and the alternative you rejected, and keep the diff focused.
4. **Schemas first.** Write Pydantic request, response, and tool-argument models with constraints that match the data dictionary (enums, lengths, `Decimal` money, UTC datetimes).
5. **Persistence.** If the schema changes, update the models and generate an Alembic migration, then review the autogenerated diff.
6. **Business logic.** Put it in `service.py`. Use async I/O through injected sessions and clients, keep transactions short, and never await an external provider inside a transaction.
7. **Boundary.** Add a thin router or WebSocket handler, plus dependencies for session, settings, clients, and auth. Map exceptions through the registered handlers.
8. **External I/O.** Go through an adapter behind a `Protocol`, with timeouts, bounded retries only where they are safe, and lifecycle owned by `lifespan`.
9. **Tests.** Write unit tests (service with fakes) and integration tests (ASGITransport plus an isolated DB) covering the happy path, validation failures, auth failures, and timeouts or cancellation when async. For side effects, add idempotency and DNC/opt-out tests.
10. **Docs.** Update `README.md`, `.env.example` (placeholders only), and the decisions table in `CLAUDE.md` if a decision was made.
11. **Quality gate.** Run `uv run ruff format .`, `uv run ruff check .`, and `uv run pytest`, plus the type checker if one is configured. Fix the failures and run again.
12. **Self-review.** Run the `async-review` checklist over the diff, and `websocket-review` if streaming code changed.

## Expected outcomes checklist

- [ ] The contract is written down, and any open questions were answered by the user
- [ ] Schemas validate at the boundary, and API schemas are separate from ORM models
- [ ] No blocking calls in async code; clients are reused from lifespan; timeouts are set
- [ ] Customer binding and authorization are enforced in backend code
- [ ] A migration exists for every schema change
- [ ] Tests were added or updated and run, with the results reported verbatim
- [ ] Docs and `.env.example` are updated, with no secrets anywhere
- [ ] The diff contains only what the feature needs

## Common failure modes

- Building ahead: generic base classes, unused config, placeholder modules.
- Creating a new `httpx.AsyncClient` or engine inside a request.
- Awaiting the LLM or Twilio while holding a DB transaction.
- Trusting a `customer_id` that came from the LLM or the request body when it should come from call context.
- Retrying a call placement or link send after a timeout and causing a duplicate side effect.
- Tests that pass only because the mock never exercises the failure path.

## Reporting

Report what changed (files), why (the design choice and trade-off), the exact quality-gate commands with their real results, and anything skipped or left unresolved. Never report tests as passing unless they ran and passed in this session.
