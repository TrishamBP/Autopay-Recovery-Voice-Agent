# Database and synthetic data

## Engine and sessions

- Use SQLAlchemy 2.0 async only: `create_async_engine`, `async_sessionmaker(expire_on_commit=False)`, `AsyncSession`, and typed `Mapped[...]` / `mapped_column` models. Don't use the legacy `Query` API or sync `Session` in app code.
- Get one session per request or unit of work through a dependency. Never share a session across concurrent tasks or across a whole call.
- **Keep transactions short.** Never hold a session or transaction open while awaiting Twilio, the LLM, speech providers, audio playback, or the customer. Read what you need, close the transaction, do the I/O, then open a new one to write the result.
- Avoid lazy loads in async code (they raise `MissingGreenlet`). Load relationships explicitly with `selectinload` or `joinedload`, or set `lazy="raise"`.

## Driver choice (still to be decided; record the choice in CLAUDE.md)

- **SQLite + aiosqlite** (local prototype): zero setup. It allows a single writer, turns on FK enforcement only with `PRAGMA foreign_keys=ON` per connection, has limited `ALTER TABLE` (use Alembic `render_as_batch=True`), and has no native timezone type.
- **PostgreSQL + asyncpg**: proper concurrency and `timestamptz`. Needs a running server.
- Whichever is chosen, keep portable SQL. Don't use dialect-specific features outside `database.py` or migrations without noting it.

## Schema conventions

- Names are `snake_case`, tables plural (`customers`, `payment_history`). Set a `MetaData(naming_convention=…)` so constraints and indexes get deterministic names for Alembic.
- Natural IDs from the dataset (`CUS-1001`, `SUB-2001`, `HIST-0001`, `NOTE-0001`) stay unique business keys, whether or not they are also primary keys. Choose once and document it.
- Add foreign keys on every relationship, indexes on FK columns and lookup columns (`phone_number`, `call_sid`), `UNIQUE` where the data dictionary says unique, and `CHECK` constraints for amounts (`> 0`, `0 <= amount_paid <= amount_due`) and enums.
- Money is `Numeric(10, 2)`. Timestamps are `DateTime(timezone=True)` stored in **UTC**. Use `server_default=func.now()` and `onupdate` for `created_at`/`updated_at`.
- Keep customer profile, current payment, payment history, notes, and call data in separate tables. Expected tables beyond the workbook: `call_sessions` (call/stream SIDs, status, limits), `conversation_turns`, `tool_executions` (args, result, idempotency key), `callback_requests`, `payment_claims`, `note_audit`, and outcome fields per the data dictionary. Add each only when the feature needs it.
- Derived metrics (`payments_on_time_6m`, `payment_reliability_score`, …) are computed from `payment_history` in a query or view, not stored and hand-maintained.
- Every schema change ships as an Alembic migration (`uv run alembic revision --autogenerate -m "…"`). Review the autogenerated diff before committing, and never edit a migration that has already been applied.

## Queries

- Use the SQLAlchemy Core/ORM builders only. Raw SQL goes through `text()` with bound parameters, never f-strings or concatenation.
- The LLM never produces SQL or column names. Tools call typed service methods.
- Side-effecting writes that tools trigger carry an idempotency key with a `UNIQUE` constraint, so retries and duplicate model calls are harmless.

## Workbook import (later task; scripts/ only)

- The workbook is seed input, not the production database. Read it with `openpyxl` in an offline script, never inside the server process.
- Validate before writing: sheet names, column sets, types, enum values, FK integrity, uniqueness, and the data dictionary's cross-field rules. Reject the whole import on any error and list every error.
- Convert IST-naive timestamps to UTC (`Asia/Kolkata`). Parse amounts as `Decimal`.
- Make it deterministic and idempotent: the same workbook yields the same rows. Never overwrite existing data silently. Either refuse when the target isn't empty or require an explicit `--replace` flag that runs in one transaction.
- Don't import `Call_Scenarios` into tables the agent can read. It is evaluation-only, so keep it in test fixtures or a separate eval table.
